## 1. 一页结论

1. 这个实验测的是 P3 测试集全体 2,305,679 人在观察期 11/18–30（共 13 天）内，处理组比对照组的转化率高多少。
   我们根据 `user_id` 使用了哈希盐进行伪随机 50 : 50 分组，分为处理组 T 组与对照组 C 组，向处理组 T 组的用户发放分期 0 手续费优惠券。

2. 拿第 1 档做主检验，是因为生产中本来就打算发给这一段人。结果 95% CI [−0.257, +0.351]pp，无法区分 H0 与区间内的其他值：
   第 1 档未检出效应，CI 上界 0.351pp，不能据此说券无效。模拟中注入的效应是 0.1pp，比这一档的 MDE 0.479pp 小，计算得出功效只有 8.5%。

3. 发 10% 的券时，根据增量转化来说，按估计增量来发券，发给估计增量最高的第五档，增量转化为 1,383 单。
   按分数发券增量 231 单，低于随机发 760.8 单，因为分数最高的人就是高购买倾向用户群体，本身购买决定很低程度会被发券影响。

4. 加上成本后，跟第三条相比，按分数发从增量少变成了 k ≥ 5% 时发多少都亏本，因为第一档人群不发券也会购买，发券后的增量利润抵不上发券的成本。
   而按估计增量发（发 10% 时），虽然都仍有盈利，但是趋势也是随着 k 变大而 ROI 降低，到 k = 15% 时 ROI 已经只剩 +0.10。

5. 首先我们使用了 A/A 模拟，证明了在两组都不发券、真实效应为 0 的实验中，全体 50 / 1000 次误报（5.0%），第 1 档 39 / 1000（3.9%），
   都在合格区间 37–64 内，误报率和名义的 5% 对得上。
   然后我们使用了 SRM 来检验输入的分组数据本身是否有问题，比如一组的人是否被漏记，检验通过才能进行下一步，
   对于 SRM 本身，我们也设计了正反两组实验证明了 SRM 自身的可靠性，正式分组 p = 0.0175，不报警。
   最后，我们使用了还原检验，用 1000 次盐重新分组，看 95% CI 是不是真的 95% 的时候盖住真值、以及估计有没有偏差，
   结果是两次共 44 行，盖住真值 940–970 次（94.0%–97.0%）；第一次有 4 行偏差出界，用新的 1000 个盐复跑，一行也没重现，没有发现偏差。

6. 对照组的结果（转化率、GMV）是真实数据；处理组的结果是真实数据 + 我们注入的效应，效应的大小和形状、券成本的结构都是假设。
   因此前面效应有多大、发给谁更赚的数字都来自模拟，检验的是方法能不能把已知的效应还原出来，不是券的真实效果。哪些真、哪些假的明细见第 2 节。

## 2. 哪些是真的，哪些是模拟的

- **真实数据**：直接来自数据集，或由真实数据算出、现实中本来就会有的数。
- **模拟**：造出来顶替本该观测到、实际上却没有的结果。
- **假设**：我们定的规则或参数，没有数据支持。

| 项 | 归类 | 理由 |
| --- | --- | --- |
| 人群（测试集 2,305,679 人） | 真实数据 | 就是 P3 的测试集，人没有造也没有删 |
| 分组（谁进处理组） | 模拟 | 分组方法（对 `user_id` 加盐哈希、50 : 50）同真实实验，但没有人真的收到券 |
| 模型分数和十分位 | 真实数据 | P3 冻结的模型对真实特征（11/04–17）打的分，不依赖分组；上线时拿到的就是这个分数 |
| 对照组的转化 `y0` | 真实数据 | 测试集 11/18–30 的真实标签 |
| 对照组的 GMV `gmv0` | 真实数据 | 观察期内真实 purchase 事件的 `price` 之和（`build_gmv.py`） |
| 处理组的转化 `y1` | 模拟 | `y0` + 注入的效应：分组前给全体造好，每档在没买的人里抽 round(τ × n) 人翻成 1 |
| 被翻成购买的人的 GMV | 模拟 | 从同一档真实买家的 GMV 里随机抽（含假设：边缘买家花得一样多） |
| τ 的数值和形状 | 假设 | 我们自己定的，没有业界依据 |
| 券成本 k | 假设 | k 取 0、5%、10%、15% 四个值是我们定的 |
| 拿到券的买家全部用券 | 假设 | 用券率是我们定的，真实用券率可能低于 100%，所以成本是上界 |

**预注册的提交顺序**：每一步的判据都在计算之前单独 commit 并 push，PR 用 merge commit 合并。
merge commit 可以看到每一步的时间线，能够证明预注册是在看到结果之前写下的。而 squash 把多条 commit 压成一条，看不出互相的先后顺序，
无法证明预注册是否在看到结果之前写下的。例：#73 的 `db019b0`（还原检验的预注册）早于 `10ca3d6`（第一次结果）。

「真值」只有模拟才有（第 5 节注入），现实的实验里没有这一列。GMV 无货币单位。

## 4. 局限和没做的

### 模拟带来的局限

- **效应是注入的**：τ 的数值和形状（单峰、峰在第 5 档）是假设，没有业界依据。第 3 节的结果说明的是「这套方法能不能把已知的效应还原出来」，**不是券的真实效果**（第 5 节）。
- **单调假设**：只把不买翻成买，不设负效应（收到券后观望、推迟到 12 月）。实验只测得到每档的净效应，个人层面的反向效应无法识别（第 5 节）。
- **被券说动的人花多少**：被翻的人的 GMV 是从同档真实买家里抽的，等于假设边缘买家和本来就买的人花得一样多。若边缘买家买得更便宜，GMV 效应被高估（第 5 节）。
- **没注入客单价效应**：本来就买的人发券后花的钱不变。BNPL 常见的客单价提升没有模拟，所以 GMV 效应偏保守（第 5 节）。
- **券成本**：假设拿到券的买家全部用券，所以成本是上界；k 只取四个假设值；m 各档相同（第 7 节）。
- **只算了 13 天的短期利润**：复购（LTV）会让发券**更**划算，提前购买会让发券**更不**划算，两者都不在数据里（第 7 节）。
- **还原检验只检验分组的随机性**：「哪些人被翻」由种子 20261005 固定，不在检验范围内（第 8 节）。
- **策略对比只基于一次分组的估计**：换一次分组，按估计增量的排序可能卡在别的档（第 7 节）。

### 数据和方法上的局限

- 测试集的 ρ 比验证集小，所以 CUPED 的缩减只到预测的六到七成。三个候选原因都**没验证**：特征窗口里 11-14 到 11-16 的断档、观察期含黑五、模型漂移。决定暂不深挖（第 6 节）。
- `price` 没有货币单位，GMV 和利润只能比相对大小（第 5 节）。
