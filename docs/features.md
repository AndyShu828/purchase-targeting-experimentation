# 特征表（P2）

> 三个截止日的特征表与标签表，由 `scripts/build_features.py` 生成（WSL，`PTE_ENV=wsl`）。
> 代码在 `src/pte/features/`；每组的 SQL 逻辑由 Andy 在 DuckDB 上写成，PySpark 版逐数对账一致。
> **本文件随特征组增加而更新**：偏好、趋势、会话三组，以及活跃度组的「会话数」、意向组的「浏览到加购转化率」尚未加入。

## 1. 三个截止日

截止日 = **标签窗口第一天**。特征读 `event_date < cutoff`，标签读 `event_date >= cutoff`（`docs/incident_2019_11_15.md` 第 4.3 节）。

| 用途 | 截止日 | 特征窗口 | 标签窗口 | 样本量 | 正例 | 正例率 |
| --- | --- | --- | --- | --: | --: | --: |
| 训练 | 2019-10-15 | 10/01–10/14 | 10/15–10/28（14 天） | 1,688,868 | 97,593 | 5.78% |
| 验证 | 2019-11-01 | 10/18–10/31 | 11/01–11/14（14 天） | 1,793,124 | 89,662 | 5.00% |
| 测试 | 2019-11-18 | 11/04–11/17 | 11/18–11/30（**13 天**） | 2,305,679 | 102,290 | 4.44% |

- **样本 = 截止日前 14 天内有任意事件的用户**（决定 2026-09-24）。14 天以上沉睡后回来买的、以及标签窗口里才第一次出现的新用户（冷启动）不在范围内
- **测试集标签只有 13 天**：数据到 11-30 为止。跨集合比较正例率时要按天归一，或者直接说明
- **验证集标签缺 5.84 小时**（11-14 18:09 之后没有购买记录，断档），接受，报告里注明
- **测试集标签含黑五**（11-29 购买数约 +30%），正例率略被抬高
- 每个特征组的回看窗口 `window_days` 目前都是 14 天，和人群一致

输出位置：`<features_dir>/<split>/features` 和 `<features_dir>/<split>/labels`（Parquet）。
**特征表和标签表分开写**：P3 训练时按 `user_id` 拼接；P3 批量评分和 P4 实验打分只读特征表，因为那时还没有标签。

## 2. 特征

「没有定义就是 NULL，0 次就是 0」：计数、合计在窗口内没发生时为 0；平均值、距今天数、比率在分母为 0 或事件不存在时为 NULL。
LightGBM 原生处理 NULL；逻辑回归基线要在 P3 补值（加缺失指示列），**补值统计量只在训练集上算**。

| 组 | 特征 | 定义 | NULL 何时出现 |
| --- | --- | --- | --- |
| 活跃度 | `n_events` | 窗口内事件数 | — |
| | `n_views` / `n_carts` | 按类型计数 | — |
| | `active_days` | 有事件的不同日期数 | — |
| | `days_since_last_event` | 截止日 − 最后一次活动的日期（最小为 1） | 窗口内无事件 |
| 购买 | `n_purchases` / `purchase_days` / `total_spend` | 购买次数、有购买的天数、金额合计（原始值） | — |
| | `*_per_day`（三列） | 上面三项 ÷ **有效天数** | — |
| | `avg_price` | `total_spend / n_purchases` | 窗口内没买过 |
| | `days_since_last_purchase` | 截止日 − 最后一次购买的日期 | 窗口内没买过 |
| 意向 | `cart_abandon_rate` | 未购的 (会话, 类目) 对 ÷ 有加购的对；剔除与断档重叠的会话 | 窗口内没有（可信的）加购对 |

**有效天数**（`src/pte/features/outage.py`）= `window_days` − 与购买断档（11-14 18:09:37 → 11-16 08:32:34，38.3825 小时）重叠的时长。
训练、验证为 14；测试为 12.40。决定 2026-09-25：**比率列是主特征集，原始计数留作敏感性对照**。
假设购买在时间上均匀分布，而断档正好压在大促尖峰上，所以只能部分修正。
`avg_price` 是比值，不需要修；`days_since_last_purchase` 修不了，只能注明。

**会话**：30 分钟无事件即切开，在 `(user_id, user_session)` 内切（`src/pte/features/sessions.py`）。
**先按特征窗口过滤事件，再切会话**：跨越截止日的会话在截止日被截断，否则它在截止日之后的购买会泄漏进特征。
